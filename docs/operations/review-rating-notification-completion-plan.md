# 内容审核、用户评级与反馈通知补完实施文档

文档日期：2026-05-11

## 1. 背景

当前系统已经具备用户认证、文章发布、AI 内容分析、推荐流、关注、互动、通知和审计日志等主体功能，但仍有三个影响设计目标完整性的缺口：

1. 文章发布流程不是严格的“发布前审核”。当前文章先写入数据库，再触发 AI 分析；如果 AI 分析失败，文章仍可能已进入公开内容集合。
2. 用户综合行为评级较弱。当前用户评级主要来自历史文章 AI 评分均值，缺少对审核结果、被举报/隐藏、正向互动等行为信号的综合计算。
3. 用户对内容处理结果的反馈通知不足。系统已有通知中心，但发布后的 AI 审核结果没有形成明确通知闭环。

本文档用于约束后续补完实现，使第 4 章中相关设计目标与代码实现保持一致。

## 2. 实施目标

### 2.1 内容发布前审核状态流

新增文章审核状态字段，使文章从创建开始即进入审核状态，AI 分析完成后再决定是否公开展示。

文章状态设计如下：

| 状态 | 含义 | 是否进入公开列表/推荐 |
| --- | --- | --- |
| `PENDING_REVIEW` | 已提交，等待 AI 审核 | 否 |
| `PUBLISHED` | AI 审核通过，正常公开 | 是 |
| `LOW_PRIORITY` | 可公开，但推荐优先级降低 | 是 |
| `REVIEW_REQUIRED` | 需要人工复核 | 否 |
| `REJECTED` | 未通过审核 | 否 |

AI 决策与文章状态映射如下：

| AI 决策 | 文章状态 |
| --- | --- |
| `ALLOW` | `PUBLISHED` |
| `LOW_PRIORITY` | `LOW_PRIORITY` |
| `REVIEW` | `REVIEW_REQUIRED` |
| `REJECT` | `REJECTED` |

公开文章列表、关注流、推荐流、评论和 reaction 只允许作用于 `PUBLISHED` 与 `LOW_PRIORITY` 内容。作者本人和管理员可以查看自己的待审核、复核和拒绝内容详情。

### 2.2 用户综合行为评级

用户评级不再只由文章平均分组成，而是综合以下信息：

- 内容质量：历史文章 AI 评分，包括专业度、友好度、理性度、合法性。
- 审核结果：低优先级、复核、拒绝内容会带来合规扣分。
- 互动反馈：用户内容收到的点赞、评论、收藏、完整阅读、关注作者等正向信号。
- 负向反馈：用户内容收到的隐藏和举报等负向信号。

综合评分输出内容包括：

- 内容质量分。
- 合规分。
- 互动反馈分。
- 综合分。
- 等级：`A`、`B`、`C`、`D`。
- 风险信号列表。

推荐排序中的作者质量继续使用用户表中的 `professionalism` 和 `friendliness` 字段，并在 AI 分析持久化后根据审核结果加入扣分。

### 2.3 用户反馈通知机制

文章发布后，系统必须向作者发送明确的处理结果通知。

通知类型新增如下：

| 通知类型 | 触发场景 |
| --- | --- |
| `CONTENT_REVIEW_APPROVED` | 内容审核通过 |
| `CONTENT_REVIEW_LIMITED` | 内容可发布，但被降低展示优先级 |
| `CONTENT_REVIEW_REQUIRED` | 内容进入复核 |
| `CONTENT_REVIEW_REJECTED` | 内容未通过审核 |
| `CONTENT_REVIEW_FAILED` | AI 审核失败，内容进入复核 |

通知内容应包含用户可理解的状态、处理原因和下一步提示。通知中心展示这些消息，并计入未读数。

此外，用户内容获得互动反馈时也需要进入通知中心：

| 通知类型 | 触发场景 |
| --- | --- |
| `COMMENT` | 其他用户评论了当前用户发布的动态 |
| `ARTICLE_REACTION` | 其他用户对当前用户发布的动态添加 emoji 反馈 |
| `REPLY` | 其他用户回复了当前用户的评论 |
| `COMMENT_REACTION` | 其他用户对当前用户的评论添加 emoji 反馈 |

互动通知只在他人触发时生成，用户对自己内容的评论或 emoji 反馈不产生通知，避免通知中心出现自触发消息。

## 3. 实施步骤

1. 数据库结构补充：为 `article` 增加审核状态、AI 决策、风险等级、审核原因、建议和审核时间字段。
2. AI 服务补充：AI 分析持久化时同步更新文章审核状态，并在更新用户基础评分时纳入审核扣分。
3. 博客服务补充：发布文章时先创建 `PENDING_REVIEW` 内容，再调用 AI 服务，最后根据结果返回文章状态。
4. 可见性控制补充：公开列表、推荐流、关注流、评论、reaction 和推荐事件只对公开状态内容开放。
5. 用户评级补充：用户评级接口输出内容质量、合规、互动反馈和综合等级。
6. 通知机制补充：文章审核完成后向作者发送结果通知。
7. 前端展示补充：文章卡片、发布结果和通知中心展示审核状态与处理结果。

## 4. 验收标准

- 新发布内容在 AI 处理前为 `PENDING_REVIEW`。
- AI 决策为 `ALLOW` 的内容进入公开列表和推荐流。
- AI 决策为 `LOW_PRIORITY` 的内容可公开，但推荐分中体现风险惩罚。
- AI 决策为 `REVIEW` 或 `REJECT` 的内容不进入公开列表、关注流和推荐流。
- 作者可以在发布结果或通知中心看到处理状态。
- 用户评级接口返回综合评分、等级和风险信号。
- 审计日志中记录文章创建和 AI 审核结果。
- 未公开内容不能被普通用户评论或 reaction。
- 他人评论当前用户动态时，当前用户通知中心出现评论提醒。
- 他人对当前用户动态添加 emoji 反馈时，当前用户通知中心出现 reaction 提醒。
