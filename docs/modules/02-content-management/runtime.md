# 社交内容发布与管理模块运行机制文档

## 内容发布流程

1. 登录用户在前端发布动态。
2. 前端调用 `POST /api/articles`。
3. `blog_service` 校验内容、清洗文本并写入 `article`。
4. 新文章初始状态为 `PENDING_REVIEW`。
5. `blog_service` 调用 `ai_service` 执行内容分析。
6. AI 返回评分、标签、风险等级和处理决策。
7. 文章状态根据 AI 决策更新：
   - `ALLOW` -> `PUBLISHED`
   - `LOW_PRIORITY` -> `LOW_PRIORITY`
   - `REVIEW` -> `REVIEW_REQUIRED`
   - `REJECT` -> `REJECTED`
8. 系统向作者发送审核结果通知，并写入审计日志。

图表参考：[内容发布与审核流程](../../diagrams/modules/content-review-flow.mmd)。

## 内容可见性控制

公开内容集合只包含 `PUBLISHED` 和 `LOW_PRIORITY`。非公开内容不会进入首页、关注流、推荐流、标签聚合和普通用户评论/emoji 操作链路。

作者本人可以查看自己的待审核、复核和拒绝内容，用于获得处理反馈。管理员也可以查看非公开内容，便于后续扩展人工复核。

## 标签机制

系统同时保留主标签和多标签关系：

- `article.tag` 用于快速展示主标签。
- `article_tag` 与 `article_tag_on_article` 用于普通标签关系。
- AI 标签由 AI 内容评级模块写入，参与推荐画像和标签页展示。

## 异常处理

| 场景 | 处理方式 |
| --- | --- |
| 内容为空 | 返回校验错误 |
| 未登录发布 | 返回认证错误 |
| 非作者删除文章 | 返回权限错误 |
| AI 分析失败 | 文章转为 `REVIEW_REQUIRED`，并向作者发送审核失败/复核通知 |
| 访问非公开他人内容 | 返回文章不存在 |

## 与其他模块协作

- AI 内容评级模块决定文章审核状态。
- 通知模块向作者反馈处理结果。
- 推荐模块只使用公开内容作为候选集。
- 审计模块记录文章创建、删除和 AI 处理结果。
