# 安全日志记录与审计模块运行机制文档

## 请求追踪机制

API 网关为请求分配 `requestId`，如果请求头已经携带 `x-request-id`，则优先沿用。下游服务在响应和审计日志中保留该标识，便于排查一次请求经过哪些服务、出现何种结果。

## 审计日志机制

各服务在关键业务动作中调用审计服务写入 `audit_log`。常见动作包括：

- 登录、注册、刷新和退出。
- 文章创建、删除和 AI 分析结果。
- 评论、reaction、关注。
- 聊天线程和消息操作。
- AI 分析请求。

审计日志记录成功与失败结果，失败请求还会保留错误状态码和详情。

图表参考：[管理员监控流程](../../diagrams/modules/audit-flow.mmd)。

## 网关监控机制

网关维护内存级路由指标，包括请求次数、错误次数、请求方法、最后状态码、最后延迟和最后访问时间。运维页可以通过接口展示这些指标。

## 健康检查机制

`/api/gateway/health` 会按照路由配置聚合各上游服务地址，并请求其 `/health` 接口。结果分为：

- `ok`：全部服务正常。
- `degraded`：部分服务异常。
- `down`：全部服务异常。

## 权限边界

审计日志和管理员摘要只允许 `admin` 或 `reviewer` 角色访问。普通用户不能查看系统审计数据。

## 与其他模块协作

- 所有业务模块都可以写入审计日志。
- 运维页通过网关接口读取健康、指标和审计信息。
- 测试文档以审计和健康检查作为系统可观测性的验收依据。
