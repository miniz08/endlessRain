# 用户社交关系与互动功能运行机制文档

## 关注机制

用户关注他人时，系统在 `follow` 表中维护一条关系记录。关系状态为 `ACTIVE` 时表示关注有效；取消关注会将状态更新为移除状态。关注成功后会触发关注通知，并记录关注作者推荐事件。

关注列表和粉丝列表通过 `followerId` 与 `followingId` 查询，用户主页中的关注摘要由关注数、粉丝数和当前访问者是否已关注组成。

图表参考：[关注与通知 ER 图](../../diagrams/modules/social-notification-er.mmd)。

## 评论与回复机制

用户评论文章时，系统会校验文章是否公开。评论保存到 `comment` 表，并写入推荐事件。若评论者不是文章作者，系统会向文章作者生成评论通知。回复评论时，如果存在 `replyToUserId`，系统还会向被回复用户生成回复通知。

## Emoji 反馈机制

文章和评论均支持 emoji 反馈。用户点击同一 emoji 时，系统会在“添加”和“取消”之间切换。添加 emoji 时会：

- 写入 `article_reaction` 或 `comment_reaction`。
- 更新推荐事件。
- 向内容作者或评论作者发送 reaction 通知。

用户对自己内容的 reaction 不会产生通知。

## 聊天机制

聊天模块以 `chat_thread` 表表示两个用户之间的固定会话，以 `chat_message` 保存消息。用户在线时，WebSocket 会将新消息实时推送给会话双方；用户离线或刷新页面后，可以通过 REST 接口读取历史消息。

图表参考：[单对单聊天流程](../../diagrams/modules/chat-flow.mmd)。

## 与其他模块协作

- 通知模块负责互动提醒。
- 推荐模块接收评论、reaction、关注等行为事件。
- 认证模块负责确认当前操作用户。
- 审计模块记录评论、删除、reaction 等关键操作。
