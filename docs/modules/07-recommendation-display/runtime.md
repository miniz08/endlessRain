# 基于评级机制的推荐与展示控制功能运行机制文档

## 推荐流运行机制

1. 用户打开首页推荐流。
2. 系统加载公开状态的文章候选集。
3. 系统读取文章 AI 标签、文章评分、作者评分、用户画像和已看记录。
4. 推荐服务计算每篇文章的推荐分。
5. 系统按推荐分和发布时间排序后返回。
6. 返回结果写入 `reco_request_log`。
7. 系统自动记录曝光事件。

图表参考：[推荐展示与行为反馈流程](../../diagrams/modules/recommendation-flow.mmd)。

## 用户画像更新机制

用户点击、停留、阅读完成、点赞、评论、收藏、关注作者、隐藏和举报等行为会写入 `reco_event`。系统根据行为权重和时间衰减重新计算用户兴趣标签向量和作者亲和度。

## 展示控制机制

文章展示受审核状态和风险等级影响：

- `PUBLISHED`：正常进入推荐候选。
- `LOW_PRIORITY`：可以公开，但推荐分受到风险惩罚。
- `REVIEW_REQUIRED`、`REJECTED`、`PENDING_REVIEW`：不进入公开推荐和关注流。

## 关注流机制

关注流先查询当前用户所有 `ACTIVE` 关注对象，再拉取自己和被关注用户的公开文章，按时间和质量展示。关注流也会记录推荐请求和曝光事件。

## 与其他模块协作

- 内容模块提供文章状态和标签。
- AI 模块提供内容评分和 AI 标签。
- 用户评级模块提供作者质量信号。
- 社交互动模块提供用户行为事件。
